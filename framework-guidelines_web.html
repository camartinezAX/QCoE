Monorepo Architecture

💡
Your code lives inside your project folder. You never need to touch another team's folder. Shared utilities come from @axos-qe/shared.
📦 Axos.QE.Web/ ├── package.json ← Root: workspaces, shared devDeps, engine ├── package-lock.json ← Single lockfile for the entire repo ├── packages/ │ └── shared/ ← @axos-qe/shared (npm workspace) │ ├── index.js ← Barrel export: test, expect, helpers, Data │ ├── fixtures/ ← base.fixture.js, global-setup, global-teardown │ ├── utils/ ← helpers.js, data.js, browserstack.js │ └── config/ ← playwright.base.config.js, browsers.json │ ├── projects/ ← One folder per team / application │ ├── Axos.QE.Enr.Web/ ← Enrollment Web (team-owned) │ │ ├── package.json ← @axos-qe/enr-web │ │ ├── playwright.config.js │ │ ├── .env ← Project settings (included with defaults) │ │ ├── src/ ← pages/, locators/, fixtures/ │ │ ├── suites/ ← Test spec files │ │ └── data/env/ ← qa.json, uat.json, stg.json, prod.json │ │ │ ├── Axos.QE.OutSys.Web/ ← OutSystems Web (team-owned) │ │ └── (same skeleton) │ │ │ └── Axos.QE.Crypto.Web/ ← Crypto Web (team-owned) │ └── (same skeleton) │ ├── tools/ ← Cross-cutting scripts (Allure, BrowserStack, health-check) ├── .github/workflows/ ← Reusable CI + per-project callers └── docs/ ← This guide + team communication

Do:
- From repo root, run: npm install

- cd into projects/Axos.QE.Enr.Web (or whichever project I'm working on)

- If "Cannot find module '@playwright/test'" → run npm install from repo root
- If "Cannot find module '@axos-qe/shared'" → run npm install from repo root
- To verify repo structure: npm run health-check (from repo root)

Tag System

⚠️
Tags are how you control what runs. Get them right and your CI / local runs are always properly scoped to your team's tests.

📐 Format

Composite tag: @{Project}_{Level}_{Feature} — scopes to project + level + feature

Simple tags: @Sanity, @Smoke, @Login — cross-project filtering

Project Prefixes: @Enr Enrollment Web @OutSys OutSystems
Levels: Sanity Smoke Regression
Features: Login Dashboard Accounts Transfers

💻 Example Test

javascript
// Describe gets project + feature tags
test.describe('Login @Enr_Login @Login', () => {

  // Test gets composite + simple tags
  test('OLB Secure Login @Enr_Sanity_Login @Enr_Smoke_Login @Sanity @Smoke', async ({ page }) => {
    // test implementation ...
  });

});

Environment & Data

🔐 .env (per project)

Each project has its own .env with sensible defaults already included. Edit to override.

dotenv
TEST_ENV=UAT
TEST_USERNAME=              # Leave blank → use data/env/uat.json
TEST_PASSWORD=              # Set values → override JSON creds

BROWSERSTACK_ACCESS_KEY=
PW_HEADLESS=1
PW_PROJECT=chromium
RETRIES=1

📊 data/env/uat.json (per project)

Test data records per environment. Each ID can have different credentials and URLs.

  "TD_001": {
    "Username": "TestUser",
    "Password": "SecurePass",
    "BaseUrl": "https://secure.uat.axosbank.com"
  }
}

Page Objects (Functional Style)

💡
Functions, not classes. Receive page as a parameter. Import helpers from @axos-qe/shared. Locators stay local to your project.

✅ Correct (Functional)

// src/pages/login.page.js
const locators = require('../locators/login.locators');
const { helpers } = require('@axos-qe/shared');

async function login(page, { username, password, baseUrl }) {
  await page.goto(baseUrl + '/login');
  await helpers.inputText(page, locators.usernameInput, username);
  await helpers.inputText(page, locators.passwordInput, password);
  await helpers.clickElement(page, locators.signInButton);
}

module.exports = { login };

❌ Wrong (Class-Based)

// DON'T do this
class LoginPage {
  constructor(page) {
    this.page = page;
  }
  async login(username, password) {
    await this.page.goto('/login');
    await this.page.fill('#user', username);
  }
}

module.exports = LoginPage;

📝 Using in Tests

javascript
const { test, expect } = require('../../src/fixtures');
const { login } = require('../../src/pages/login.page');
const { Data } = require('@axos-qe/shared');

test.describe('Login @Enr_Login @Login', () => {
  test('OLB Secure Login @Enr_Sanity_Login @Sanity @Smoke', async ({ page }) => {
    const creds = Data.getCredentials('TD_001');
    await login(page, {
      username: creds.Username,
      password: creds.Password,
      baseUrl: creds.BaseUrl,
    });
  });
});

Locator Patterns

✅ DO — XPath with Normalization

// Case-insensitive, whitespace-normalized
"//*[translate(normalize-space(text()),
  'ABCDE...Z', 'abcde...z') = 'sign in']"
"(//input)[1]"
"//button[@type='submit']"
"//a[contains(@href, 'dashboard')]"

❌ DON'T — Fragile CSS Chains

// Avoid these
"#app > div.main > form > input"
".btn-primary.submit-form.large"
"[data-testid='login-form'] input"

Allure Reporting (v3)

Results are written to projects/YourProject/allure-results/<runId>/. Each project is isolated — no clashes.

bash
# From your project directory
npm run clean                     # Clean previous results
npm test                          # Run tests
npm run allure:serve              # Generate + open report

# Or step by step:
npm run allure:generate           # Generate only
npm run allure:open               # Open existing report
✅
Allure v3 is TypeScript-based — no Java required. Verify with npx allure --version.

Code Quality Rules

✅ Use Helper Functions ▼

✅ Correct

await helpers.waitForElement(page, locator);
await helpers.clickElement(page, locator);
await helpers.inputText(page, locator, text);

❌ Wrong

await page.waitForSelector(locator);
await page.click(locator);
await page.fill(locator, text);
❌ No Commented Code▼

Remove all commented code before committing. Git tracks history.

❌ No Hard-Coded Waits▼

Never use page.waitForTimeout() or setTimeout. Use smart waits from helpers.

✅ Correct File Placement▼
TypeLocation
Page Objectsprojects/YourProject/src/pages/{feature}.page.js
Locatorsprojects/YourProject/src/locators/{feature}.locators.js
Testsprojects/YourProject/suites/{##}_{Feature}/{test}.spec.js
Test Dataprojects/YourProject/data/env/{env}.json
