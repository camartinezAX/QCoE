File Naming Conventions

✅ Correct Patterns

File Type Pattern Example
Business Object {vertical}.js login.js, megaMenu.js, bank.js
Locators {vertical}.locators.js login.locators.js, bank.locators.js
Spec Files {feature}.spec.js login.spec.js, deposit.spec.js
Suite Folders {##}_{VerticalName}/ 02_Login/, 06_Bank/
Data Files {##}_{vertical}.xlsx 02_login.xlsx, 06_bank.xlsx

✅ DO

File Names 
// BizObjects
login.js
megaMenu.js
bank.js

// Locators
login.locators.js
megaMenu.locators.js

// Suite Folders
02_Login/
06_Bank/

❌ DON'T

Anti-Patterns 
// ❌ Wrong - Random naming
mssqlDBEnrollmentFlows.js

// ❌ Wrong - Using PascalCase
MyLoginTests.spec.js

// ❌ Wrong - Hyphens instead of dots
bank-locators.js

// ❌ Wrong - Single digit prefix
6_Bank/
⚠️
Database Utilities
Database-related code should go in src/utils/, not in bizobjects. Example: src/utils/enrollmentDb.js

Spec File Structure

💡
The Golden Rule
Your describe blocks should mirror the user's navigation path through the app.

Why Separate Describes?

Different menu items lead to completely different screens and flows, even if they're under the same parent section.

javascript 
// ✅ CORRECT - Separate describes for different screens
describe('Mega menu -> Profile -> Personal Information', () => {
  it('Update Contact Information @Sanity_MegaMenu', async () => {
    // Tests for Personal Information screen
  });
});

describe('Mega menu -> Profile -> Business Information', () => {
  it('Read-Only Validation @Sanity_MegaMenu', async () => {
    // Tests for Business Information screen
  });
});

Tag System

Tags are used for filtering tests during execution. Follow this hierarchy for consistent test organization.

Combined Tags (Preferred)

Use this format for all tests

@Sanity_Login @Sanity_MegaMenu @Sanity_Bank

Regression Priority Tags

Only for ADO-classified regression tests

@Regression_P0 @Regression_P1 @Regression_P2

Work Item Tags

For ADO traceability

@2193771 @2193995

📊 Complete Tag Reference

Category Format Example Notes
Sanity @Sanity_{Vertical} @Sanity_Login, @Sanity_MegaMenu Primary tag format for sanity tests
Regression @Regression_{Vertical} @Regression_Bank, @Regression_Invest Primary tag format for regression tests
Regression Priority @Regression_P0/P1/P2 @Regression_P0 Only for tests classified in ADO
Work Item @{ADO_ID} @2193771 For traceability to ADO work items

✅ Correct Tags

// ✅ Combined format (preferred)
it('Reset Password @Sanity_Login')

// ✅ With work item ID
it('Validate Deposit @Regression_Bank @2193771')

// ✅ With ADO priority (only if classified in ADO)
it('Critical Flow @Regression_Bank @Regression_P0')

❌ Wrong Tags

// ❌ Wrong - Separate tags (use combined)
it('Reset Password @MegaMenu @Sanity')

// ❌ Wrong - Tags with spaces
it('Reset Password @Sanity Login')

// ❌ Wrong - P0/P1/P2 without ADO classification
it('Some Test @Regression_P0')
⚠️
Priority Tags Rule
@Regression_P0, @Regression_P1, and @Regression_P2 should only be used for tests that are explicitly classified with priority levels in Azure DevOps.

Locator Patterns

💡
Cross-Platform Required
Every locator must have both android and ios selectors.
javascript 
// src/locators/megaMenu.locators.js
module.exports = {
  // Simple element
  megaMenuHamburger: {
    android: "//*[contains(@content-desc,'hamburger Icon')]",
    ios: "//*[contains(@label,'hamburger Icon')]"
  },
  
  // Section with prefix
  hA_streetAddressEntry: {
    android: "(//*[@text='Home Address']/.../descendant::EditText)[1]",
    ios: "//XCUIElementTypeTextField[@name='HAStreetAddressInputField']"
  },
  
  // Dynamic locator with placeholder
  locator_by_text: {
    android: "-android uiautomator:new UiSelector().text(\"__TEXT__\")",
    ios: "//XCUIElementTypeButton[contains(@name, \"__TEXT__\")]"
  }
};

📌 Common Prefixes

Prefix Meaning Example
hA_ Home Address hA_streetAddressEntry
mA_ Mailing Address mA_zipCodeEntry
bi_ Business Information bi_companyName
otp_ OTP Related otp_sendNewCodeButton

Business Object Patterns

Business objects encapsulate page interactions. They should be reusable and readable.

📝 Method Naming Conventions

Pattern Use Case Example

enter{Data} Input actions enterEmploymentDetails()

Code Quality Rules

❌ No Commented Code Blocks ▼

Remove all commented code before committing. Version control tracks history.

❌ Wrong

async function validateAddress() {
  await helpers.clickWhenVisible(saveButton);
  // await helpers.strictWait(5000);
  // await helpers.scrollUntilVisible(streetSelector);
  // var streetSelector = `//*[@text='Home']`;
}

✅ Correct

async function validateAddress() {
  await helpers.clickWhenVisible(saveButton);
}
❌ No Duplicate Code - Reuse Helpers ▼

Always use existing helpers from src/utils/helpers.js.

❌ Wrong

await browser.pause(5000);
const elem = await $(selector);
await elem.click();

✅ Correct

await helpers.clickWhenVisible(selector, { 
  timeout: 5000 
});
❌ No Improper File Placement ▼

Files must be placed in the correct directory based on their purpose.

File Type ❌ Wrong ✅ Correct
Database Utils src/bizobjects/mssqlDBEnrollmentFlows.js src/utils/enrollmentDb.js
Helpers src/locators/myCustomHelpers.js src/utils/myCustomHelpers.js
✅ Always Include Author Documentation ▼ 
describe('Bank -> Deposit', () => {
  /**
   * @VijayLachwani          ← Author tag
   */
  it('Validate Deposit Limit @Sanity_Bank @2193771', async () => {
    // Test implementation
  });
});
